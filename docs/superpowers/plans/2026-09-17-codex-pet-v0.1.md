# Codex Pet V0.1 Implementation Plan

**Goal:** Deliver a Windows-verified transparent desktop pet that displays real quota data from the local Codex CLI App Server.

**Architecture:** React renders only normalized quota state. Rust owns the App Server child process, JSON-RPC transport, refresh lifecycle, tray, window, and persistence.

## Tasks

1. Initialize the repository, Tauri scaffold, documentation, and build toolchain.
2. Build the quota domain with test-first response normalization and time formatting.
3. Build and manually verify the transparent draggable pet shell and tray.
4. Build the Codex App Server client with fake-server tests and a real local quota read.
5. Connect live quota state, refresh events, polling, retry, and stale-state behavior to the UI.
6. Add position persistence, Windows acceptance checks, final review, and public GitHub delivery.

## Constraints

- Never read or persist Codex credentials, account identifiers, prompts, conversations, or project source.
- Prefer `rateLimitsByLimitId.codex`; fall back to `rateLimits`; derive labels from `windowDurationMins`.
- Lock mode is whole-window click-through and must remain recoverable through the tray.
- Every behavior change follows a failing-test-first cycle and every stage is verified before commit.
